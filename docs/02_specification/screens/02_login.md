# ログイン画面

**ルーティング**: `/login`  
**対象ユーザー**: owner（staff 個別ログインは後続フェーズ）  
**主な目的**: Webアプリへのログイン

## 前提

- フェーズ1は**最小MVPとして** owner ログインのみ実装する（staff 個別ログインは後続フェーズ）
- **メールアドレスは収集・保存しない**（個人情報を持たない方針。詳細は備考）
- ログインIDは開発者が発行する。リクルートからサロンに割り振られるID（サロンボードのID等）をそのまま用いる
- 初期パスワードは開発者が発行し，初回ログイン時に本人が変更する（`/change-password` 参照）
- サインアップ画面・招待画面は提供しない

## シナリオ

開発者から案内されたログインIDと初期パスワードを受け取る  
→ ログインユーザーが `/login` を開く  
→ ログインIDとパスワードを入力する  
→ 「ログイン」を押す  
→ 初回ログイン時は `/change-password` へ遷移してパスワードを変更する  
→ 2回目以降は `/dashboard` へ遷移する  

## 画面構成

```text
ロゴ / サービス名

見出し: ログイン
説明文: 発行済みアカウントでログインしてください

ログインID入力
パスワード入力
ログインボタン

注記: パスワードを忘れた場合は管理者にお問い合わせください
```

## 入力項目

| 項目 | 内容 |
|---|---|
| ログインID | 開発者が発行したID（リクルート割当のIDを使用） |
| パスワード | 発行済み初期パスワード，または変更後のパスワード |

## 操作

| 操作 | 挙動 |
|---|---|
| ログイン | ログインID/パスワードで認証する。成功時は `/dashboard` に遷移する（初回は `/change-password`） |

## バリデーション

- ログインIDが空の場合はエラー表示
- パスワードが空の場合はエラー表示

## 状態

| 状態 | 表示 |
|---|---|
| 送信中 | ログインボタンをローディング状態にし，再送信を防ぐ |
| 認証成功（初回） | `/change-password` に遷移する |
| 認証成功（2回目以降） | `/dashboard` に遷移する |
| 認証失敗 | フォーム下部に「ログインIDまたはパスワードが正しくありません」を表示する |
| セッションあり | `/login` を表示せず `/dashboard` にリダイレクトする |

## 備考

- 新規登録リンクは置かない
- **パスワードを忘れた場合はセルフサービスで再設定できない**（メールを保存しないため再設定リンクの送り先がない）。開発者が初期パスワードを再発行し，初回変更フローに戻す運用とする
- 認証基盤は Supabase Auth を使う。ログインIDは内部的に合成メールアドレス（例: `{loginId}@auth.salon-ai.invalid`）へ変換して Supabase Auth に渡す。実在するメールアドレスは扱わず，メール送信も行わない
- フェーズ1の運用はサロンごとに1アカウント（共有）とするが，1サロン内に複数アカウント可のスキーマ設計は維持する
- SPファースト。入力欄とボタンは片手操作しやすい縦並びにする
