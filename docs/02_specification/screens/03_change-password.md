# パスワード変更画面

**ルーティング**: `/change-password`  
**対象ユーザー**: owner（staff 個別ログインは後続フェーズ）  
**主な目的**: 初回ログイン時の強制パスワード変更と，任意のパスワード変更

## 前提

- **認証済みユーザーのみアクセスできる**（未ログインは `/login` へリダイレクト）
- メールアドレスを保存しないため，メールによるパスワード再設定は行わない（`02_login.md` 備考参照）
- 用途は2つある
  - 初回ログイン時: 開発者発行の初期パスワードから本人のパスワードへ強制変更する。変更完了までアプリ本体（`/dashboard`）へ進めない
  - 任意変更: ログイン後にいつでもパスワードを変更できる

## シナリオ

### 初回ログイン時

`/login` で初期パスワードによる認証が成功する  
→ `/change-password` へ自動遷移する  
→ 新しいパスワードを入力して保存する  
→ 完了後に `/dashboard` へ遷移する  

### 任意変更

ログイン済みユーザーが `/change-password` を開く  
→ 新しいパスワードを入力して保存する  
→ 完了後に `/dashboard` へ戻る  

## 画面構成

```text
見出し: パスワードの変更
説明文（初回のみ）: 初期パスワードから新しいパスワードに変更してください

現在のパスワード入力（任意変更時のみ。初回強制変更時は表示しない）
新しいパスワード入力
新しいパスワード（確認）入力
保存ボタン

ダッシュボードへ戻るリンク（初回強制変更時は表示しない）
```

## 操作

| 操作 | 挙動 |
|---|---|
| 保存 | パスワードを更新し，初回変更フラグを解除して `/dashboard` へ遷移する |
| ダッシュボードへ戻る | `/dashboard` に戻る（初回強制変更時は表示しない） |

## バリデーション

- 任意変更時は現在のパスワードが空なら保存不可，一致しない場合はエラー表示
- 新しいパスワードが空なら保存不可
- 確認用パスワードが一致しない場合はエラー表示

## 状態

| 状態 | 表示 |
|---|---|
| 保存中 | 保存ボタンをローディング状態にし，再送信を防ぐ |
| 変更完了 | 「パスワードを更新しました」を表示して `/dashboard` へ遷移する |
| 変更失敗 | フォーム下部にエラーメッセージを表示する |
| 未ログインでアクセス | `/login` にリダイレクトする |

## 備考

- 初回変更フラグは Supabase Auth の user_metadata で管理する想定（実装詳細は Step 2 で確定する）
- 任意変更では現在のパスワードの入力を必須とする（セッション窃取時にパスワードを乗っ取られないようにするため）。初回強制変更はログイン直後のため省略する
- パスワード強度ルールは Supabase の標準要件に従う。独自要件はフェーズ1では追加しない
- SPファースト。入力欄とボタンは片手操作しやすい縦並びにする
