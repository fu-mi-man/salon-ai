# パスワードリセット画面

**ルーティング**: `/reset-password`  
**対象ユーザー**: owner / staff  
**主な目的**: パスワード再設定メールの送信と，新しいパスワードの設定  

## 前提

- パスワードリセットメールは Supabase Auth 標準機能を使用する
- 画面の役割は 2 段階ある
- 1段階目: メールアドレスを入力して再設定メールを送る
- 2段階目: メール内リンクから戻ってきたユーザーが新しいパスワードを設定する

## シナリオ

ログインユーザーが `/login` から「パスワードを忘れた場合」を押す  
→ `/reset-password` でメールアドレスを入力する  
→ 再設定メールを送信する  
→ メール内リンクを開く  
→ 新しいパスワードを入力して保存する  
→ 完了後に `/login` へ戻る  

## 画面構成

### メール送信前

```text
見出し: パスワード再設定
説明文: 登録済みメールアドレスに再設定リンクを送信します

メールアドレス入力
送信ボタン
ログインへ戻るリンク
```

### リンク経由でアクセスした後

```text
見出し: 新しいパスワードを設定

新しいパスワード入力
新しいパスワード（確認）入力
保存ボタン
```

## 操作

| 操作 | 挙動 |
|---|---|
| 再設定メール送信 | 入力メールアドレスに Supabase Auth の再設定メールを送る |
| 新しいパスワードを保存 | トークン検証後にパスワードを更新し，完了メッセージを出して `/login` へ遷移させる |
| ログインへ戻る | `/login` に戻る |

## バリデーション

- メールアドレスが空，または形式不正なら送信不可
- 新しいパスワードが空なら保存不可
- 確認用パスワードが一致しない場合はエラー表示

## 状態

| 状態 | 表示 |
|---|---|
| メール送信成功 | 「再設定メールを送信しました」を表示する |
| メール送信失敗 | フォーム下部にエラーメッセージを表示する |
| トークン有効 | 新しいパスワード入力フォームを表示する |
| トークン無効 | 「リンクの有効期限が切れています。再度メールを送信してください」を表示する |
| 再設定完了 | 「パスワードを更新しました。再度ログインしてください」を表示して `/login` へ遷移する |

## 備考

- セキュリティ上，メール送信成功時は「該当メールアドレスが存在するか」を明示しない
- パスワード強度ルールは Supabase の標準要件に従う。独自要件はフェーズ1では追加しない
